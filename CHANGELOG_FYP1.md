# FYP I — what was changed, why, and what was verified  (2026-11-22)

All numbers below come from the INTERIM panel (price_mcap_panel_v1.csv, 326,819 rows, before Gigi's Binance gap-fill).
Re-run the same commands on the final panel; the locked config does not change.

## Aron_fixed/  (backtest engine + allocators)         tests: 19/19 pass;  review_C: 16 PASS / 0 FAIL (was 3 FAIL)
| Defect found in the original | Fix |
|---|---|
| Weekly return = 6 days (Monday close -> Sunday close), one day lost per week | enter at close of Sunday cut-off, exit at next Sunday close = 7 days |
| Single-observation fallback inverted the ratio (+10% shown as -9.1%) | removed; uses last traded price in the week |
| Coin without price silently 0% (LUNA showed no loss) | held coin valued at last traded price (LUNA -99.99%); coin without price at cut-off is not tradeable; counts logged |
| 10% cap by clip+renormalise gave 20% weights | water-filling inside the engine; optimisers use the cap as a constraint |
| Risk parity returned exactly 1/N (objective ~1e-12, solver never moved) | rescaled problem; risk contributions equal to <1% (tested) |
| market_cap needed a 'market_cap' column the panel does not have -> silent equal weight | reads panel `mcap`; proportional to market cap (tested) |
| Minimum variance: dropna() wiped the window when any member lacked data -> silent equal weight | imputes day mean, drops coins with <60 days, Ledoit-Wolf on 180 days (planning report), logged fall-backs |
| All four allocators produced identical returns on real data | all allocators now differ (tested) |
| Only 4 of 6 allocators; no slippage; rf, info_cutoff unused | + mean_variance, black_litterman (no views = prior), btc_buy_hold; fee 15 bps + slippage 5 bps; cutoff used |

## Hayden_updated/  (factor pipeline)                  tests: 35 pass, 2 FYP-II tests not verifiable offline (need `arch`, `xgboost`)
* `forward_return_wide`: terminal-return rule only for coins B flagged `end_reason == collapsed` (LUNA, FTT). Using the panel-wide last date made labels depend on the future (Monero gap) -> look-ahead audit FAILED on real data; now PASSES (4/4 dates, difference 0).
* Liquidity rule 3 (28-day avg volume >= US$1M) was in the group agreement but NOT in the code: added (`screening.min_avg_volume_usd`).
* Monotonicity threshold: float noise (-0.7999999999999999 < 0.8) failed a factor at exactly 0.8: compared after rounding (test added). No verdict changed.
* Black-Litterman delta: fixed 2.5 implied a median 109%/yr market return -> `implied_sharpe: 0.5` mode.
* prepare_data.py (complete adapter): drops B's `exclude` rows and weekly forward-filled rows, splices MKR->SKY (1:24000), FTM->S, MATIC->POL, maps 7 coins B could not map (DOT, NEAR, HBAR, MATIC/POL, OP, INJ, CAKE), removes stablecoins + PAXG, writes coverage report. review_B on its output: 12 PASS / 7 WARN / 0 FAIL.
* review_C.py: independent return recompute no longer depends on the factor code.
